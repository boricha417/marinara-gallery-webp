# 갤러리 webp 변환 1.8.3 (Marinara Engine 2.5.0)

채팅방 갤러리의 PNG 삽화를 브라우저에서 WebP로 다시 인코딩해 서버 용량을 줄이는 개인 확장입니다. 엔진은 건드리지 않고 순정 갤러리·채팅·캐릭터 갤러리 API만 사용합니다. **대화·롤플레이 방 전용이며, 게임 모드 방에서는 작동하지 않습니다**(아래 "알아둘 점").

## 설치

1. **설정 → 고급 → 위험 구역**에서 "외부 확장 가져오기 허용"을 켭니다.
2. **설정 → 애드온 → 외부 확장**에서 이 저장소의 zip 또는 폴더(`manifest.json`, `extension.js`, `extension.css`)를 가져옵니다. GitHub 확장 관리자 확장을 쓰면 저장소 주소를 등록해 업데이트도 받을 수 있습니다.
   설치용 zip은 저장소에 올려 둔 `갤러리 webp 변환_v1.8.3.zip`입니다(파일을 열고 **Download** 버튼). 저장소 전체를 "Download ZIP"으로 받으면 폴더가 한 겹 더 있어 바로 설치되지 않습니다.
3. 가져온 확장은 꺼진 상태로 들어옵니다. 코드 해시를 확인하고 **승인 → 활성화**합니다. 코드가 바뀔 때마다 다시 승인해야 합니다.

## 들어가는 자리

- **갤러리 헤더의 설정(톱니) 버튼** — 갤러리를 창으로 띄웠을 때는 핀 버튼 왼쪽, 채팅 설정 안에 접혀 있을 때는 갤러리 섹션 제목 줄(별도 창 열기 버튼 왼쪽)에 들어갑니다. 누르면 설정 팝오버가 열립니다.
- **선택 바의 두 버튼** — 갤러리에서 `선택`을 누르면 나오는 `선택 다운로드 / 선택 삭제` 옆에 `선택 변환`, `선택 프롬 복사`가 붙습니다. 바가 좁으면 아이콘만 보이고, 마우스를 올리면 이름이 뜹니다.

## 설정 팝오버

긴 설명은 각 항목 오른쪽의 `?` 버튼을 누르면 펼쳐집니다. 값에 따라 달라지는 안내(품질 설명, 예상 용량, 자동 변환 상태 줄)만 항상 보입니다. 순서는 갤러리 그리드 → 변환 품질 → 생성 삽화 자동 변환 → 사본도 함께 변환 → 일괄 작업입니다.

| 항목 | 설명 |
| --- | --- |
| 갤러리 그리드 | 기본(2열) / 3열 / 4열 / 5열. 모든 방에 공통으로 기억됩니다. |
| 변환 품질 | 70~100을 5단위로, 기본 95. 95는 눈으로 구분이 어렵고 PNG의 1/8 정도입니다. **100은 브라우저가 무손실로 인코딩**해 PNG의 절반 정도이고, 사본까지 만들면 PNG 1장보다 커집니다(팝오버에 경고 표시). 자동 변환과 수동 변환 모두 이 값을 씁니다. |
| 생성 삽화 자동 변환 | 켠 **뒤에** 생성된 삽화만 10초 간격 점검으로 자동 변환합니다(처음 본 뒤 8초 대기). 마리나라를 열어 둔 브라우저 탭이 화면에 보일 때만 동작하고(다른 탭이나 창 뒤에 있으면 쉼), 놓친 삽화는 다음에 그 채팅방을 열면 처리합니다. 켜면 아래에 **마지막 점검 시각·결과·오류**가 보이고 `지금 점검` 버튼으로 바로 돌릴 수 있습니다. 실패한 삽화는 3번까지 다시 시도합니다. 기본 꺼짐. |
| └ 변환 완료 알림 표시 | 자동 변환을 켰을 때 그 아래에 나오는 하위 토글. 자동 변환이 끝났을 때 알림을 띄울지 정합니다. 끄면 결과는 상태 줄에서만 보이고 실패만 알림으로 뜹니다. 기본 꺼짐. 알림은 PC·폰 모두 입력창을 가리지 않게 화면 위쪽에 뜹니다. |
| 사본도 함께 변환 + 사본 대상 | 토글을 켜면 아래에서 선택한 갤러리(캐릭터 / 페르소나)에 연결된 그림은 그곳에도 WebP를 한 장씩 올립니다. 선택하지 않은 갤러리 쪽 연결은 옛 PNG와 함께 사라집니다. 토글 기본 꺼짐, 대상 기본은 캐릭터만. |
| 예상 용량 | 지금 설정으로 변환하면 PNG 1장 대비 몇 %가 되는지 보여줍니다(채팅 1장 + 사본 장수). 100%를 넘으면 경고로 바뀝니다. |
| 일괄 작업: 이 채팅방의 모든 삽화 변환 | PNG 전부를 **오래된 순서로** 변환해 갤러리 순서를 유지합니다. 진행률과 취소 버튼이 뜨고, 취소해도 이미 끝난 삽화는 그대로 남습니다. 다시 누르면 남은 PNG만 이어서 합니다. |
| 일괄 작업: 선택한 갤러리에 전체 사본 만들기 | 이 방 삽화 중 위에서 선택한 갤러리에 없는 것을 복사하여 그곳에 올립니다. 채팅방을 지워도 남기고 싶을 때 쓰는 일회성 버튼입니다. |

### 순정 엔진과 다른 점: 파일 수

순정 엔진은 **설정 → 이미지 생성 → "생성된 이미지를 캐릭터 갤러리에 자동 저장"**(기본 켜짐)이 켜져 있으면 삽화를 생성할 때 **파일 1장**을 저장하고, 그림에 등장한 캐릭터 갤러리와 페르소나 갤러리에는 그 파일을 가리키는 기록만 추가합니다(한 장을 세 곳에서 보여줌). 이 설정은 Illustrator 에이전트 안이 아니라 앱 설정에 있고, 끄면 채팅 갤러리에만 저장됩니다. 그 "가리키는 기록"을 만드는 API는 바깥에 없어서, 확장은 사본을 원하면 갤러리마다 WebP를 한 장씩 더 올립니다.

| 품질 | 채팅 1장 | + 캐릭터 사본 (2장) | + 캐릭터·페르소나 사본 (3장) |
| --- | --- | --- | --- |
| 90 | 약 9% | 약 18% | 약 27% |
| 95 | 약 13% | 약 25% | 약 38% |
| 100 (무손실) | 약 57% | 약 114% | 약 171% |

PNG 1장 = 100% 기준, 크롬 캔버스 인코딩 실측값입니다.

## 변환 한 장이 하는 일

1. **미리 확인.** 관련 방(삽화 소유 방, 지금 열린 방, 같은 그룹의 분기·게임 세션 방, 연결된 방)의 메시지를 읽어 고칠 수 없는 자리가 없는지 보고, (사본 토글이 켜져 있으면) 모든 캐릭터·페르소나 갤러리에서 이 삽화의 사본을 찾습니다. 다른 방이 404면 지워진 방으로 보고 넘어가지만, 그 밖의 오류는 건너뜀 사유가 됩니다.
2. 원본을 받아 캔버스로 WebP 인코딩
3. 같은 프롬프트·제공자·모델·크기로 채팅 갤러리에 업로드
4. (토글 켜짐) 선택한 캐릭터·페르소나 갤러리에도 같은 파일·같은 정보로 업로드. 서버가 적은 생성 시각이 새 채팅 기록과 55초 넘게 벌어지면 되돌립니다.
5. **생성이 진행 중이면 기다리기.** 롤플레이·대화 모드 입력창의 보내기 버튼이 중지 아이콘이거나 갤러리의 생성 버튼이 바쁜 동안은 작업당 한 번 최대 60초 기다리고(진행 표시에 "생성이 끝나길 기다리는 중"), 그래도 계속이면 남은 삽화는 "PNG로 남김"으로 미룹니다. 생성이 끝난 뒤 다시 돌리면 남은 것만 이어서 변환합니다. 백그라운드 삽화 생성 중에는 입력창이 중지 아이콘을 숨기므로, 갤러리가 열려 있지 않으면 이 감지가 빠질 수 있습니다.
6. **적용 직전에 다시 읽기.** 관련 방의 메시지를 다시 읽어 그 사이 생성기가 더한 첨부나 바뀐 답변 버전을 반영한 뒤, 첨부(스와이프 번호를 명시)와 본문 속 직접 링크(이 서버 주소만, 링크 단위)를 새 주소로 교체
7. **교체 뒤 확인.** 고친 메시지를 서버에서 직접 다시 읽어(스와이프 기록, 없으면 그 방 목록을 다시 받음) 옛 주소를 쓰는 자리가 남아 있으면(그 사이 누군가 옛 주소를 다시 적은 경우) PNG를 지우지 않고 실패로 알립니다. 이때는 PNG와 WebP가 둘 다 남습니다.
8. 옛 PNG 삭제(서버가 연결된 캐릭터 갤러리 기록도 같이 정리)
9. 핀 고정 목록(브라우저 저장소)의 주소 교체, 마리나라 화면 캐시 갱신 요청

변환·사본 만들기는 한 번에 하나만 돕니다. 같은 탭 안의 잠금에 더해 확장 저장소(서버)에 잠금 표를 적어 두므로 다른 탭이나 기기에서 돌리면 "다른 탭이나 기기에서 작업 중"으로 거절됩니다. 저장소에 원자적 잠금이 없어서 "표를 쓰고 잠시 뒤 다시 읽어 내 표가 남았는지 확인"하는 방식이며, 둘이 거의 같은 순간 시작하면 나중에 쓴 쪽만 진행합니다. 작업 중에는 60초마다 표를 갱신하되, 갱신 전에 다른 기기의 표로 바뀌어 있으면 덮어쓰지 않고 이쪽 작업을 삽화 경계에서 멈춥니다. 3분 넘게 갱신이 없는 표는 끊긴 것으로 보고, 해제는 내 표일 때만 합니다(실패하면 몇 번 더 시도하고 알림). 새로고침으로 끊긴 내 작업의 표는 그 탭이 기억하고 있어 다음 작업이 그냥 넘어갑니다(탭마다 따로 기억하므로 다른 탭의 표는 내 것으로 보지 않습니다). 다른 기기의 표가 남아 막힐 때는 설정 팝오버 아래에 그 표와 **작업 표 지우기** 버튼이 나오며, 그쪽 작업이 끝난 게 확실할 때만 누르세요. 마지막 작업 결과도 팝오버에 남습니다.

## 큰 방에서의 메시지 읽기

메시지 목록은 엔진 화면과 같은 방식으로 최신부터 50개씩 페이지 단위로 받아 오래된 순으로 합칩니다(1.8.0). 메시지 1,520개짜리 방(한 번에 받으면 32MB) 실측에서 한 페이지는 보통 1~2MB, 긴 메시지가 몰린 페이지도 4MB 미만이었고, 삽화 두 장 변환이 3초 안에 끝났습니다. 한 번에 받으면 메시지가 많은 방은 응답 하나가 수십 MB라 브라우저가 해석하는 동안 화면이 까맣게 멈출 수 있었는데, 이제 한 응답이 수 MB를 넘지 않고 페이지 사이마다 화면이 그려집니다. 진행 표시에 "메시지 읽는 중 n페이지…"가 뜹니다. 받는 총량은 같으므로 큰 방은 그만큼 시간이 걸리며, 변환 순서(갤러리 생성일 오래된 순)는 바뀌지 않습니다. 지금 열린 방도 관련 방에 포함되므로, 작은 방을 변환하면서 아주 큰 방을 열어 두면 그 방 목록도 읽습니다.

## 서버 요청 제한

마리나라 서버는 기본적으로 1분에 600회까지만 요청을 받고 그 뒤는 429(Too many requests)로 거절합니다. 확장은 삽화 한 장당 10회 안팎의 요청을 쓰며(방 전체 메시지 목록은 작업당 한 번만 받고, 고친 메시지는 서버 응답으로 갱신하며, 적용 직전에는 고칠 메시지의 스와이프만 새로 읽음), 분당 420회 아래로 스스로 속도를 맞춥니다. 그래도 429가 오면 서버가 알려 주는 시간만큼 쉬었다가 다시 보냅니다. 429는 요청을 처리하기 전에 거절하는 것이라 업로드가 중복되지 않습니다. 기다리는 동안은 진행 표시에 사유가 뜹니다. 큰 방의 전체 변환은 그만큼 오래 걸릴 수 있으니 탭을 열어 두세요.

## 확장만으로는 완전히 못 막는 것

이 확장은 마리나라의 일반 API만 쓰고, 그 API에는 "이 값이 그대로일 때만 바꿔라"(조건부 갱신)나 원자적 잠금이 없습니다. 그래서 다음 두 상황은 가능성을 크게 줄였을 뿐 0은 아니며, 네트워크 지연이나 탭 정지로 그 틈이 길어질 수도 있습니다.

- **마지막 읽기와 쓰기 사이에 생성기가 같은 메시지에 첨부를 더하거나 답변 버전을 바꾸는 경우.** 생성 중 보류와 교체 뒤 확인으로 대부분 걸러지지만, 교체 뒤 확인은 "옛 주소가 남았는지"만 보므로 그 틈에 들어왔다가 덮어써진 다른 첨부까지는 알아채지 못합니다. 변환은 생성이 끝난 뒤에 돌리는 것이 가장 안전합니다.
- **두 기기가 거의 같은 순간에 작업을 시작하는 경우.** 잠금 확인 창보다 빠르면 둘 다 진행할 수 있습니다. 한 기기에서만 돌리세요.
- **변환이 도는 동안 그 방의 분기(연결된 방)를 새로 만드는 경우.** 관련 방 목록은 작업을 시작할 때 한 번 읽으므로, 그 뒤에 생긴 분기에 복사된 첨부는 확인 대상에 들어가지 않고 옛 PNG가 지워질 수 있습니다. 전체 변환이 끝난 뒤에 분기를 만드세요.

이 둘을 완전히 닫으려면 엔진 쪽에 조건부 갱신과 제자리 변환 기능이 필요합니다.

### 건너뛰거나 되돌리는 경우

PNG를 지우기 전에 확인이 끝나지 않으면 그 삽화는 **PNG를 남기고 건너뜁니다.** 결과 알림과 자동 변환 상태 줄에 "건너뜀 n장"과 이유가 표시됩니다.

- 관련 방·메시지·스와이프·캐릭터 갤러리 조회가 하나라도 실패했을 때 ("없음"으로 오인해 지우지 않습니다)
- 비활성 답변 버전(스와이프)의 **본문**에 직접 링크가 있을 때 (엔진에 그 본문을 고치는 API가 없습니다. 첨부는 고칠 수 있습니다)
- 사본 토글이 켜져 있는데 사본 업로드가 실패했거나 너무 늦었을 때 — 이때는 **이미 만든 사본과 새 WebP를 지우고** PNG를 남깁니다 (실패로 집계)
- `전체 사본 만들기`에서 서버 시각을 확인하지 못했을 때 — 기기 시계로 대신하지 않고 중단합니다
- 첨부 교체 도중 실패하면 PNG와 WebP가 둘 다 남고 일부 메시지만 WebP를 가리킵니다. 깨지지는 않으며, 다시 변환하면 WebP가 한 장 더 생기니 수동으로 정리하세요 (실패로 집계)

### 자동 변환이 삽화를 고르는 기준

- 자동 변환을 켤 때 갤러리에서 가장 새 삽화의 생성 시각(서버 시계)을 기준으로 잡고, 그 뒤 삽화만 봅니다.
- 이 기기에서 처음 본 뒤 8초가 지나고 **최근 메시지에 첨부로 붙어 있는** 삽화만 변환합니다. 엔진은 갤러리 등록 뒤에 첨부하므로, 첨부가 보이면 생성이 끝난 것입니다.
- 첨부가 없는 삽화(직접 올린 것, 아직 생성 중인 것)는 시간이 지나도 자동으로 건드리지 않습니다. 직접 올린 삽화는 선택 변환으로 바꾸세요.
- 실패한 삽화는 3번까지 다시 시도합니다.

## 삭제 연동

마리나라는 채팅 갤러리에서 삽화를 지울 때 캐릭터 갤러리의 "같은 삽화 복사본"도 지웁니다. 복사본 판정은 (원본 ID 연결) 또는 (60초 이내 생성 + 프롬프트·제공자·모델·크기 동일 + 파일 내용 동일)입니다. 확장은 같은 규칙으로 사본을 찾되, 파일 내용은 크기를 먼저 보고 두 파일을 받아 SHA-256 해시로 비교합니다. 확인하지 못하면 "사본 없음"이 아니라 건너뜀으로 처리합니다.

- 변환 때 토글로 만든 사본은 같은 파일을 연달아 올리므로 **지금처럼 같이 지워집니다**. 로컬 2.5.0에서 캐릭터·페르소나 양쪽 모두 확인했습니다(characterCopiesRemoved 1, personaCopiesRemoved 1).
- `선택한 갤러리에 전체 사본 만들기`로 만든 사본은 생성 시각이 원본과 멀어 **채팅방에서 지워도 남습니다**. 이것이 의도한 동작입니다. 그래서 생성 2분이 안 된 삽화는 건너뛰고 나중에 다시 누르라고 안내합니다.
- 사본을 찾는 범위는 모든 캐릭터·페르소나 갤러리입니다(목록 API로 전부 조회). 엔진이 원본 ID로 연결된 사본을 전체에서 지우는 것과 같은 범위예요. 캐릭터가 많으면 변환 작업 한 번당 캐릭터 수만큼 갤러리 조회가 한 번씩 더 일어납니다.
- 이 규칙은 엔진의 호환용 코드에 기댑니다. 엔진이 바꾸면 캐릭터 갤러리에서 따로 지워야 할 수 있습니다.

## 알아둘 점

- **크롬·엣지 계열 전용(PC·안드로이드).** 아이폰 사파리는 캔버스 WebP 인코딩을 지원하지 않아 변환 버튼이 비활성화되고 자동 변환 상태 줄에 그 이유가 뜹니다. 그리드와 프롬프트 복사는 어디서나 됩니다.
- **안드로이드 웹앱(PWA)에서 자동 변환이 안 되면** 설정 팝오버의 자동 변환 상태 줄을 먼저 보세요. "점검 실패: ... 실패 (0)" 또는 "Failed to fetch"가 보이면 오래된 서비스 워커가 API 호출을 막는 경우이니, 웹앱을 지우고 다시 설치하거나 크롬에서 사이트 데이터를 지운 뒤 다시 열면 됩니다. 자동 변환 설정은 서버에 저장되어 모든 기기에서 같습니다.
- 변환본의 생성일은 변환한 시각이 됩니다. 업로드 API가 날짜를 받지 않아서입니다. 선택 변환은 선택한 그림들이 갤러리 위쪽으로 올라오고(그들끼리 순서는 유지), 전체 변환은 순서가 그대로입니다.
- 마리나라가 NovelAI 응답 PNG의 텍스트 청크에 덧붙이는 요청 기록은 사라집니다. 반면 NovelAI가 알파 채널에 숨겨 두는 생성 정보(stealth pnginfo)는 픽셀과 함께 옮겨지고 WebP가 투명도 채널을 무손실로 저장하므로 변환 뒤에도 남아, novelai.net/inspect에서 계속 읽힙니다. 갤러리에서 보이는 프롬프트·모델·크기는 DB 값이라 그대로 유지됩니다.
- **자동 변환이 한 삽화를 포기하는 기준(1.8.3).** 실패한 삽화뿐 아니라 "다른 답변 버전 본문에 직접 링크" 같은 영구 사유로 건너뛴 삽화도 3번까지만 다시 시도하고, 그 뒤로는 자동 점검에서 제외합니다(선택 변환은 가능). "생성이 진행 중이라 미룸"은 일시적이라 횟수에 세지 않습니다. 1.8.2 이하에서는 영구 사유 삽화 한 장이 남아 있으면 점검 때마다 관련 방 전체를 다시 읽고 같은 알림이 반복됐습니다.
- **게임 모드 방은 지원하지 않습니다(1.8.2).** 게임 모드 삽화는 메시지 첨부가 아니라 스토리보드 키프레임이 그림 id로 붙들고 있고, 그 연결을 바꾸는 API가 없습니다. 변환 뒤 옛 PNG를 지우면 스토리보드의 그림이 끊기므로, 게임 갤러리에는 버튼을 넣지 않고 변환·자동 점검·사본 만들기도 방 모드를 읽어 거절합니다. 방 정보를 읽지 못하면 역시 진행하지 않습니다. 1.8.1 이하를 게임 모드 방에서 쓰지 마세요.
- 핀 고정된 그림은 변환 후 새로고침해야 새 주소로 보입니다.
- `선택 프롬 복사`는 오래된 순서로, 항목 사이에 빈 줄 하나를 두고 복사합니다. 프롬프트가 없는 직접 업로드 그림은 건너뛰고 장수를 알려줍니다.
- 화면 갱신은 마리나라 내부 캐시에 요청하는 방식이라 엔진 구조가 바뀌면 새로고침 안내로 떨어집니다.

## 확장이 기대는 화면 표식

- 갤러리 루트: `[data-chat-settings-section$="-gallery"]`, `.mari-window[data-window$="-gallery"]` — 단, id가 `game-gallery`로 끝나는 것(게임 모드)은 제외
- 방 모드: `GET /api/chats/:id`의 `mode` (`game`이면 거절)
- 헤더 자리: `.mari-window__controls`, `.mari-drawer__header .mari-drawer__actions`
- 선택 바: 같은 부모 안의 `svg.lucide-download` / `svg.lucide-trash-2` 버튼
- 선택된 타일: `button[aria-pressed="true"] img`
- 선택 모드 종료: `button.mari-editor-action svg.lucide-x`
- 활성 방: `localStorage["marinara-active-chat-id"]`

엔진이 이 구조를 바꾸면 해당 자리만 손보면 됩니다.

## 수동 확인 항목 (2026-10-15, 로컬 2.5.0)

1. 창으로 띄운 갤러리 헤더 핀 옆에 톱니 버튼이 보인다.
2. 채팅 설정 안 갤러리 섹션 제목 줄에도 톱니 버튼이 보인다.
3. 그리드 3열 선택 시 창·섹션 모두 3열이 되고, 새로고침 뒤에도 유지된다.
4. 선택 모드에서 `선택 변환`, `선택 프롬 복사`가 다운로드/삭제 옆에 붙고, 좁은 창에서는 아이콘만 보인다.
5. 선택 변환: 2.3MB PNG → 300KB WebP, 메시지 첨부 주소·파일명·galleryId 교체, 옛 PNG 삭제, 채팅 화면과 갤러리가 새로고침 없이 갱신, 선택 모드 자동 종료.
6. 사본 토글 켜짐: 캐릭터 갤러리의 옛 PNG 복사본이 사라지고 WebP 복사본이 생긴다. 이후 채팅방에서 지우면 그 복사본도 같이 지워진다.
7. 선택 프롬 복사: 오래된 순 · 빈 줄 구분.
8. 전체 변환: 남은 PNG만 오래된 순으로 변환.
9. 자동 변환: 켠 뒤 올린 PNG가 약 10초 안에 WebP로 바뀐다.
10. 캐릭터 갤러리에 사본 만들기: 없는 그림만 올리고, 다시 누르면 0건.
11. 비활성화 시 버튼·표식·패널이 제거된다.

폰 레이아웃(시트)은 아직 실기기에서 확인하지 않았습니다.
